Unique values with DISTINCT

Tables repeat values. Many customers live in the same city. Many products share a category. When you want to know which values exist, not every row that has them, DISTINCT removes the repeats.

SELECT category FROM products;

The cure

Put DISTINCT straight after SELECT.

SELECT DISTINCT category FROM products;
Try it

Result

Home

Now each category appears once. The question changed from "what is the category of each product?" to "what categories are there?".

DISTINCT does not sort the result. Add ORDER BY if you want an order.

DISTINCT covers the whole row

With more than one column, DISTINCT looks at the combination. A row is removed only if every one of its columns matches another row.

SELECT DISTINCT state, city
FROM customers
ORDER BY state, city;
Try it

Result

statecity
DelhiDelhi
KeralaKochi
MaharashtraMumbai
MaharashtraPune
PunjabAmritsar
PunjabLudhiana
RajasthanJaipur
Tamil NaduChennai

9 rows

A state appears several times here, once for each of its cities. That is correct: the pairs are different.

This is the point people get wrong. DISTINCT is not a function that you wrap around one column. SELECT DISTINCT(state), city means exactly the same as the query above. The brackets do nothing. You cannot make one column unique and leave the others free. If you want one row for each state with something chosen from its cities, that is a job for GROUP BY.

Counting unique values

How many different cities do the customers come from? Put DISTINCT inside COUNT.

SELECT COUNT(DISTINCT city) AS cities,
       COUNT(city) AS rows_with_a_city
FROM customers;
Try it

Result

citiesrows_with_a_city
912

1 row

The first number counts each city once. The second counts every row. Comparing the two is a quick test for repeats in a column.

How many customers have ever placed an order?

SELECT COUNT(DISTINCT customer_id) AS customers_who_ordered
FROM orders;

With a filter

WHERE runs first, then the repeats are removed.

SELECT DISTINCT status
FROM orders
WHERE order_date >= '2026-06-01';

NULL counts as a value here

For DISTINCT, all the NULLs are treated as the same, and one NULL row is kept.

Do not use DISTINCT to hide a mistake

When a query that joins tables returns rows twice, it is tempting to add DISTINCT and move on. Usually the doubling means that the join is wrong, and DISTINCT hides the fault while leaving totals and counts wrong elsewhere. When you see duplicates you did not expect, find out why before reaching for DISTINCT.

It also costs time. To remove repeats, the database has to sort or otherwise compare all the rows. On a large result that is real work, so use DISTINCT when you need it and not as a habit.

DISTINCT or GROUP BY?

These two return the same rows:

SELECT DISTINCT category FROM products;
Try it

Result

category
Grocery
Stationery
Electronics
Home

4 rows

SELECT category FROM products GROUP BY category;
Try it

Result

category
Electronics
Grocery
Home
Stationery

4 rows

Use DISTINCT when you only want the list of values. Use GROUP BY when you also want a figure for each value, such as how many products each category has. That starts in the lesson after next.

Where DISTINCT sits in a query

It belongs with SELECT, before the first column. The full order is now: SELECT DISTINCT, FROM, WHERE, ORDER BY, LIMIT.
