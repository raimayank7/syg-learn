SQL in different databases

SQL is a standard, and every database product follows most of it. Each also has its own habits, a little like regional forms of one language. This page gathers the differences that beginners meet first, so that you can take what you learn here to whichever database your college or workplace uses.

The lessons on this site run on SQLite. Nearly everything in the first eighteen lessons works unchanged everywhere. The differences cluster in a few places: limiting rows, text functions, dates, automatic id numbers and changing tables.

These notes are a guide written from general knowledge of each product. Products change with each version, so treat your database's own manual as the final word.

The last form is the one in the SQL standard. SQL Server 2012 and later accepts a close relative, ORDER BY price DESC OFFSET 0 ROWS FETCH NEXT 3 ROWS ONLY. Lesson: LIMIT.

Joining text

DatabaseForm
SQLite, PostgreSQL, Oraclefirst_name || ' ' || last_name
MySQLCONCAT(first_name, ' ', last_name)
SQL Serverfirst_name + ' ' + last_name or CONCAT(...)

In MySQL, || means OR unless a setting is changed, so a query written for PostgreSQL can run there without an error and give wrong results. CONCAT also works in PostgreSQL and Oracle, though Oracle's takes only two values at a time.

This is where the products differ most. Lesson: dates.

Notice that DATEDIFF takes its dates in the opposite order in MySQL and SQL Server. Oracle uses SYSDATE for now, EXTRACT for parts, and plain addition of a number for days.

In every product, write a date in a query as '2026-03-15': year, month, day.

Quotation marks around names

Text values take single quotation marks in every product. Names of tables and columns that contain spaces or clash with a keyword need quoting, and here the products differ.

DatabaseQuoting a name
Standard SQL, PostgreSQL, Oracle, SQLite"order date"
MySQLbackticks (the key below Esc) around the name
SQL Server[order date]

The simplest course is to avoid the need: use names in small letters with underscores, such as order_date.

Division of whole numbers

SELECT 7 / 2 gives 3 in SQLite, PostgreSQL and SQL Server, where dividing two whole numbers drops the fraction. It gives 3.5 in MySQL and Oracle. Write 7 / 2.0, or multiply by 1.0, to get decimals everywhere.

Things SQLite does differently

Because the practice box runs SQLite, it helps to know where it is more relaxed than the server databases.

  • Types are not enforced. A column declared INTEGER will accept text. Server databases refuse.
  • No separate date type. Dates are kept as text or numbers.
  • Foreign keys are checked only if switched on. Elsewhere they are always checked.
  • An ordinary column beside an aggregate without GROUP BY is allowed. Elsewhere it is an error, and the lessons tell you not to rely on it.
  • ALTER TABLE is limited. It can add, rename and drop columns, but cannot change a column's type.
  • No users or permissions. GRANT and REVOKE do not exist. A SQLite database is a file, and whoever can open the file can use it.

None of this affects what you learn about queries. It only means that the practice box forgives a few things that a server would reject.

Moving between products

Someone who knows SQL well in one product is productive in another within days. The ideas carry over completely: tables, keys, joins, grouping, subqueries, window functions. What changes is a short list of function names and a few keywords. When a query fails after a move:

  1. Read the error. It usually names the function or keyword that the product does not know.
  2. Look up the job, not the name. Search the new product's manual for "add days to date" and not for the old function.
  3. Check the rules on case and on whole-number division, which change results without any error.

Which one should a beginner learn?

Whichever your course or job uses. If you have a free choice, PostgreSQL and MySQL are both free and widely used, and SQLite needs no installation at all. The practice box on this site is enough for all 26 lessons.
