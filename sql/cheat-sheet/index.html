SQL cheat sheet

The everyday SQL on one page, for people who have done the lessons and need a reminder. Each heading links to the lesson that explains it. The table and column names are those of the practice database.

The order of a query

Written order, which never changes:

SELECT   columns, aggregates
FROM     table
JOIN     other_table ON matching rule
WHERE    conditions on rows
GROUP BY columns
HAVING   conditions on groups
ORDER BY columns
LIMIT    number OFFSET number;

The database carries it out in a different order: FROM and JOIN, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT. That is why an alias made in SELECT cannot be used in WHERE.

Reading data

SELECT, WHERE, AND, OR, IN, BETWEEN, LIKE, NULL, ORDER BY, LIMIT, DISTINCT.

SELECT * FROM products;
SELECT name, price * 1.18 AS with_tax FROM products;
SELECT DISTINCT city FROM customers;
SELECT name FROM products WHERE price > 500 AND category = 'Home';
SELECT name FROM customers WHERE city IN ('Delhi', 'Mumbai');
SELECT name FROM products WHERE price BETWEEN 100 AND 300;
SELECT name FROM customers WHERE name LIKE 'A%';      -- starts with A
SELECT name FROM customers WHERE email IS NULL;       -- never = NULL
SELECT name, price FROM products ORDER BY price DESC LIMIT 3;
SELECT COALESCE(email, 'none') FROM customers;
Wildcard in LIKEMeans
%any run of characters
_exactly one character

Summaries

Functions, aggregates, GROUP BY, HAVING.

SELECT COUNT(*), SUM(stock), AVG(price), MIN(price), MAX(price) FROM products;
SELECT COUNT(DISTINCT city) FROM customers;
SELECT category, COUNT(*) AS n FROM products GROUP BY category;
SELECT category, AVG(price) FROM products GROUP BY category HAVING AVG(price) > 400;
SELECT UPPER(name), LENGTH(name), SUBSTR(name, 1, 3), ROUND(price / 3.0, 2) FROM products;

WHERE filters rows before grouping. HAVING filters groups after it. Every column in the SELECT must be in the GROUP BY or inside an aggregate.

Joins

INNER JOIN, LEFT JOIN, many tables and self joins.

SELECT o.id, c.name
FROM orders o
JOIN customers c ON o.customer_id = c.id;             -- only rows that match

SELECT c.name, COUNT(o.id) AS orders
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id            -- every customer
GROUP BY c.id, c.name;

SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;                                    -- customers with no orders

SELECT e.name, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;         -- self join
JoinKeeps
JOIN (inner)rows with a match on both sides
LEFT JOINall rows of the first table
RIGHT JOINall rows of the second table
FULL JOINall rows of both
CROSS JOINevery pairing

Subqueries and set operations

Subqueries, UNION.

SELECT name FROM products WHERE price > (SELECT AVG(price) FROM products);
SELECT name FROM customers WHERE id IN (SELECT customer_id FROM orders);
SELECT name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

SELECT city FROM customers UNION SELECT 'Goa';        -- no repeats
SELECT name FROM customers UNION ALL SELECT name FROM employees;
SELECT id FROM customers EXCEPT SELECT customer_id FROM orders;

Changing data

INSERT, UPDATE and DELETE.

INSERT INTO products (name, category, price, stock)
VALUES ('Desk Lamp', 'Home', 599, 15);

UPDATE products SET price = 70 WHERE id = 5;          -- always with WHERE
DELETE FROM orders WHERE id = 9;                      -- always with WHERE

Write the WHERE as a SELECT first and look at the rows. An UPDATE or DELETE without WHERE changes every row.

Tables

CREATE TABLE, ALTER, DROP and indexes.

CREATE TABLE reviews (
  id INTEGER PRIMARY KEY,
  product_id INTEGER NOT NULL REFERENCES products(id),
  stars INTEGER NOT NULL CHECK (stars BETWEEN 1 AND 5),
  comment TEXT,
  created TEXT NOT NULL DEFAULT '2026-01-01'
);
ALTER TABLE customers ADD COLUMN phone TEXT;
CREATE INDEX idx_orders_customer ON orders (customer_id);
DROP TABLE reviews;

PRIMARY KEYunique, not null, identifies the row

Going further

CASE, dates, views and WITH, window functions.

SELECT name, CASE WHEN price >= 1000 THEN 'premium' ELSE 'standard' END AS band FROM products;
SELECT SUM(CASE WHEN status = 'delivered' THEN 1 ELSE 0 END) AS delivered FROM orders;

WITH totals AS (SELECT customer_id, COUNT(*) AS n FROM orders GROUP BY customer_id)
SELECT AVG(n) FROM totals;

CREATE VIEW cheap AS SELECT * FROM products WHERE price < 150;

SELECT name, salary,
       RANK() OVER (ORDER BY salary DESC) AS place,
       AVG(salary) OVER (PARTITION BY department) AS dept_avg
FROM employees;

Six habits that prevent most mistakes

  1. Text in single quotation marks. Numbers without.
  2. IS NULL, never = NULL.
  3. Brackets whenever AND and OR meet.
  4. Table aliases and table.column in every join.
  5. Count a column of the right-hand table after a LEFT JOIN, not *.
  6. SELECT before every UPDATE and DELETE.
