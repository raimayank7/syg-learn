Choosing columns

SELECT * returns every column. That is handy for a first look, but most of the time you want only a few. A real table may have fifty columns, and nobody wants to read all of them to find a name and a phone number.

A missing comma or a misspelt column gives an error.

SELECT name, town FROM customers;

What the database says

Error: no such column: town

There is no column called town. The message tells you exactly that.

Why not always use the star?

  • Clarity. A query that names its columns says what it is for.
  • Speed. On big tables, fetching columns you do not need wastes time.
  • Safety. If someone adds a column to the table later, SELECT * suddenly returns something different. Named columns stay the same.

Use * when exploring. Name your columns in anything you keep.

Renaming a column with AS

The arithmetic signs are the usual ones: +, -, * for multiply and / for divide. Without the alias, the heading would be the sum itself, which is ugly. Always name a calculated column.

You can use two columns in one calculation. This is the value of the stock of each product.

A warning about dividing whole numbers

In SQLite, and in PostgreSQL and SQL Server, dividing one whole number by another gives a whole number. The fraction is dropped.

SELECT 7 / 2 AS whole, 7 / 2.0 AS with_decimals;
Try it

Result

wholewith_decimals
33.5

1 row

To keep the decimals, make one of the numbers a decimal, as in 2.0. MySQL and Oracle keep the decimals by themselves. This small difference causes many wrong averages, so remember it.

Notice also that this query has no FROM. In SQLite, MySQL, PostgreSQL and SQL Server, you can use SELECT as a calculator.

Fixed text in a column

Joining text together

The operator || glues pieces of text together. This is standard SQL and works in SQLite, PostgreSQL and Oracle.

SELECT name || ' (' || city || ')' AS customer
FROM customers;

How a simple query is laid out

SELECT column1, column2, calculation AS alias
FROM table_name;

As queries grow, each new part gets a line of its own. That layout makes long queries easy to read from top to bottom.
