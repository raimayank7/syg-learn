What SQL is, and your first query

A database is an organised store of information. A shop's database remembers its customers, its products and every order. A school's remembers students, classes and marks. SQL is the language you use to ask a database questions and to change what it holds. The letters stand for Structured Query Language. Some people say the letters one by one and others say "sequel". Both are fine.

SQL is worth learning because it is everywhere. Banks, hospitals, websites, apps and accounting software keep their data in databases that speak it. The language has changed little in decades, so what you learn here stays useful.

Tables, rows and columns

A database keeps its data in tables. A table looks like a sheet in a spreadsheet.

  • Each row is one thing: one customer, one product, one order.
  • Each column is one fact about that thing: a name, a city, a price.
  • Every table has a name, and so does every column.

Our practice database belongs to a small made-up shop. It has five tables: customers, products, orders, order_items and employees. You can see all of them on the practice database page.

Read it as a sentence: "select everything from customers".

  • SELECT says you want to read data.
  • The star * means "all the columns".
  • FROM customers names the table.
  • The semicolon ; ends the statement.

The database answers with a table of its own, called the result. Press Try it under any example to open it in the practice box, where you can change it and run it yourself. Nothing you do there can break anything. One button puts the database back as new.

Each product has an id, a name, a category, a price in rupees and the number in stock. The id column is worth noticing. It gives every row a number of its own, so that two products with the same name could still be told apart. Nearly every table has such a column. It is called the primary key.

Does the case of the letters matter?

SQL keywords are not case sensitive. SELECT, select and Select all work. By habit, most people write the keywords in capitals and the table and column names in small letters, because it makes a query easier to read. These lessons follow that habit.

When you make a mistake

If you misspell a table name, the database cannot find it and says so.

SELECT * FROM customer;

What the database says

Error: no such table: customer

The table is called customers, with an s. Error messages in SQL are short and usually name the word that caused the trouble. Read them. They save time.

What kind of SQL is this?

There are several database products: MySQL, PostgreSQL, SQL Server, Oracle, SQLite and others. All of them understand SQL, and the core of the language is the same in each. They differ in small ways, a little like the English of India, Britain and America. The practice box on this site runs SQLite. Wherever another product does something differently, the lesson tells you. There is a summary on the page about SQL in different databases.

What comes next

The next eight lessons are all about reading data: choosing columns, filtering rows, sorting and limiting. Reading is the largest part of SQL and the safest to practise, because a SELECT never changes anything.
