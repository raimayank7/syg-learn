Searching text with LIKE

The equals sign finds exact matches. Often you know only part of what you are looking for: names that start with A, products with "kg" in them, email addresses at a certain site. LIKE matches text against a pattern.

The two wildcards

A pattern is ordinary text plus two special characters.

WildcardStands for
%any run of characters, including none at all
_exactly one character

Starts with

Put the % at the end.

SELECT name FROM customers WHERE name LIKE 'A%';
Try it

Result

name
Asha Verma
Arjun Mehta

2 rows

The pattern 'A%' means "an A, then anything".

Put the % at the start.

SELECT name, email FROM customers WHERE email LIKE '%@example.com';

Contains

Put a % on both sides.

SELECT name FROM products WHERE name LIKE '%Box%';
Try it

Result

name
Geometry Box

1 row

This finds the text anywhere: at the start, in the middle or at the end, because % can also stand for nothing.

One character with the underscore

Each underscore must match exactly one character. This finds names whose second letter is a.

SELECT name FROM customers WHERE name LIKE '_a%';
Try it

Result

name
Ravi Kumar
Kabir Khan
Tara Singh

3 rows

Underscores are useful for codes with a fixed shape. The pattern '2026-0_-__' matches every date from January to September 2026.

SELECT id, order_date FROM orders WHERE order_date LIKE '2026-0_-1_';

NOT LIKE

SELECT name FROM products WHERE name NOT LIKE '% %';
Try it

Result

name
Earphones

1 row

The pattern '% %' matches any text with a space in it, so NOT LIKE returns the names made of a single word.

Capital and small letters

How LIKE treats case depends on the database.

  • In SQLite, LIKE ignores case for the English letters A to Z. That is how the practice box behaves.
  • In MySQL and SQL Server, with their usual settings, it also ignores case.
  • In PostgreSQL and Oracle, LIKE is case sensitive. PostgreSQL has a separate word, ILIKE, for a search that ignores case.
SELECT name FROM products WHERE name LIKE '%box%';
Try it

Result

name
Geometry Box

1 row

To be safe in any database, turn both sides to the same case, as the lesson on functions shows.

Combining patterns

LIKE conditions join with AND and OR like any others.

SELECT name
FROM customers
WHERE name LIKE 'A%' OR name LIKE 'S%';
Try it

Result

name
Asha Verma
Sunita Rao
Arjun Mehta

3 rows

There is no way to give LIKE a list of patterns in standard SQL. Repeat the test with OR.

Searching for a real percent sign

What if the text you want contains % or _ itself? Name an escape character with ESCAPE. Whatever follows that character in the pattern is taken as itself.

SELECT '50% off' LIKE '%\%%' ESCAPE '\' AS has_percent,
       'half off' LIKE '%\%%' ESCAPE '\' AS no_percent;
Try it

Result

has_percentno_percent
10

1 row

The result is 1 for true and 0 for false, which is how SQLite shows the answer to a test.

LIKE can be slow

A pattern that starts with % forces the database to read every row and look inside the text. On a table of a few thousand rows nobody notices. On millions of rows it is slow. A pattern with a fixed start, such as 'A%', can use an index and stays fast. Large systems that need "contains" searches use special full-text search features instead.

LIKE or equals?

If you know the whole value, use =. It is exact and fast. Use LIKE only when you need a wildcard. A LIKE without any wildcard works but tells the reader you meant something else.
