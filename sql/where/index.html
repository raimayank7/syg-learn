Filtering rows with WHERE

Choosing columns narrows a result from side to side. WHERE narrows it from top to bottom. It keeps only the rows that pass a test. This is the most used part of SQL, because a question about data is almost always a question about some of the rows.

The shape of WHERE

WHERE comes after FROM. It is followed by a condition. The database checks the condition for every row and returns the rows where it is true.

SELECT name, city
FROM customers
WHERE city = 'Delhi';
Try it

Result

namecity
Ravi KumarDelhi
Imran AliDelhi

2 rows

Only the customers from Delhi are returned. The other rows are still in the table. A SELECT never removes anything.

Comparing text

Text goes in single quotation marks.

SELECT name, category, price
FROM products
WHERE category = 'Stationery';
Try it

Result

Ball Pen pack of 10Stationery90
Geometry BoxStationery120
School BagStationery750

Leaving the quotation marks out is the most common mistake in this lesson. Without them, the database thinks Stationery is the name of a column.

SELECT name FROM products WHERE category = Stationery;

What the database says

Error: no such column: Stationery

Is text case sensitive?

It depends on the database, and this surprises people who move from one to another. In SQLite, PostgreSQL and Oracle, 'delhi' does not equal 'Delhi'. In MySQL and SQL Server, with their usual settings, it does.

SELECT name FROM customers WHERE city = 'delhi';
Try it

Result

name

0 rows

No rows came back, because in the table the city is written with a capital D. The lesson on functions shows how to compare without caring about case.

Comparing dates

In our database, dates are stored as text in the form year, month, day: '2026-03-15'. Written this way, dates sort correctly, and the comparison operators work on them just as you would hope.

SELECT id, order_date, status
FROM orders
WHERE order_date >= '2026-07-01';
Try it

Result

idorder_datestatus
162026-07-09delivered

Always write dates in year-month-day order with four digits for the year and two each for month and day. Every database understands that form. There is a whole lesson on dates later.

An alias cannot be used in WHERE

This catches everyone once.

SELECT name, price * stock AS stock_value
FROM products
WHERE stock_value > 20000;

Some databases, SQLite among them, are forgiving and accept this, so the practice box may run it. Standard SQL does not, and MySQL, PostgreSQL, SQL Server and Oracle refuse. The reason is the order in which a query is carried out: the database filters the rows first and names the columns afterwards, so at the time of the WHERE, the alias does not exist yet. Repeat the calculation in the WHERE, as in the example before this one.

The order of the parts

The parts of a query must come in a fixed order. So far: SELECT, then FROM, then WHERE. Putting WHERE before FROM is an error.
