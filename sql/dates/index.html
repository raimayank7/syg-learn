Working with dates

Almost every real table has a date in it, and almost every report is "per month" or "in the last 30 days". Dates are also the part of SQL where the databases differ most. The ideas are the same everywhere. The function names are not. This lesson teaches the ideas using SQLite, which runs in the practice box, and ends with a table of the same jobs in other products.

Dates as text in year-month-day order

Our practice database stores dates as text such as '2026-03-15'. This form, year first, then month, then day, each with leading zeros, is an international standard (ISO 8601). It has a useful property: sorting the text alphabetically also sorts the dates in time order. That is why ORDER BY order_date and comparisons with < and > have worked all along.

SELECT id, order_date
FROM orders
WHERE order_date >= '2026-06-01' AND order_date < '2026-09-01'
ORDER BY order_date;

Parts of a date

strftime formats a date using codes. It is SQLite's main date tool.

SELECT order_date,
       strftime('%Y', order_date) AS year,
       strftime('%m', order_date) AS month,
       strftime('%d', order_date) AS day
FROM orders
LIMIT 4;

Grouping by month

The most common date report. Format each date as year and month, then group by that.

SELECT strftime('%Y-%m', order_date) AS month,
       COUNT(*) AS orders
FROM orders
GROUP BY strftime('%Y-%m', order_date)
ORDER BY month;

Sales by month, joining in the prices:

SELECT strftime('%Y-%m', o.order_date) AS month,
       SUM(oi.quantity * p.price) AS sales
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
JOIN products p     ON oi.product_id = p.id
WHERE o.status <> 'cancelled'
GROUP BY strftime('%Y-%m', o.order_date)
ORDER BY month;

Quarters

There is no quarter code in SQLite, so work it out from the month.

SELECT id, order_date,
       'Q' || ((CAST(strftime('%m', order_date) AS INTEGER) + 2) / 3) AS quarter
FROM orders
LIMIT 5;

Day of the week

SELECT order_date,
       CASE strftime('%w', order_date)
         WHEN '0' THEN 'Sunday'    WHEN '1' THEN 'Monday'
         WHEN '2' THEN 'Tuesday'   WHEN '3' THEN 'Wednesday'
         WHEN '4' THEN 'Thursday'  WHEN '5' THEN 'Friday'
         ELSE 'Saturday'
       END AS weekday
FROM orders
LIMIT 5;

Adding and subtracting time

The date function takes a date and one or more changes to apply.

SELECT order_date,
       date(order_date, '+7 days') AS a_week_later,
       date(order_date, '+1 month') AS a_month_later,
       date(order_date, '-1 year') AS a_year_before
FROM orders
LIMIT 3;

Other useful changes move to the start of a period.

SELECT date('2026-03-15', 'start of month') AS first_of_month,
       date('2026-03-15', 'start of month', '+1 month', '-1 day') AS last_of_month,

Days between two dates

julianday turns a date into a count of days. Subtract two of them for the gap.

SELECT name, hired,
       CAST(julianday('2026-11-12') - julianday(hired) AS INTEGER) AS days_employed
FROM employees
ORDER BY days_employed DESC
LIMIT 4;

How long after joining did each customer first order?

SELECT c.name, c.joined, MIN(o.order_date) AS first_order,
       CAST(julianday(MIN(o.order_date)) - julianday(c.joined) AS INTEGER) AS days_to_first_order
FROM customers c
JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name, c.joined
ORDER BY days_to_first_order
LIMIT 5;

Whole years between two dates

Dividing days by 365 is slightly wrong because of leap years. A dependable way to get completed years, such as an age or years of service, is to subtract the years and take one off if the anniversary has not yet come this year.

SELECT name, hired,
       CAST(strftime('%Y', '2026-11-12') AS INTEGER) - CAST(strftime('%Y', hired) AS INTEGER)
       - (strftime('%m-%d', '2026-11-12') < strftime('%m-%d', hired)) AS full_years
FROM employees
ORDER BY hired;

Today's date

Every database can tell you the current date and time. In SQLite:

SELECT date('now') AS today, datetime('now') AS now_utc, datetime('now', 'localtime') AS now_local;

We do not show a result because it changes every day. Try it in the practice box. Note that SQLite's 'now' is in UTC, the world's reference time, unless you add 'localtime'. India is five and a half hours ahead of UTC, so late in the evening UTC the date differs.

The examples in this lesson use the fixed date '2026-11-12' so that their results stay the same. In real queries you would write date('now') in its place. "Orders in the last 30 days" becomes:

SELECT * FROM orders WHERE order_date >= date('now', '-30 days');

Dates with a time of day

A column that stores date and time together, such as '2026-03-15 14:30:00', needs care in comparisons. WHERE created = '2026-03-15' finds nothing, because no row was created at exactly midnight. Ask for a range:

WHERE created >= '2026-03-15' AND created < '2026-03-16'

This "from the start of the day, up to but not including the next day" pattern is correct in every database and lets an index be used.

Advice

  • Store dates in a date column, or as year-month-day text in SQLite. Never as day/month/year text.
  • Compare dates with ranges: >= the start and < the day after the end.
  • Group by year and month together.
  • Avoid wrapping the date column in a function inside WHERE on large tables. WHERE order_date >= '2026-01-01' AND order_date < '2027-01-01' can use an index. WHERE strftime('%Y', order_date) = '2026' cannot.
