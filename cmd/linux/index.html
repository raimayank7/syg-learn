Linux and Mac commands

The commands shared by Linux and the Mac's Terminal, grouped into pages by what they do. Examples were run with the standard GNU tools, and the output shown is what they printed. Where the Mac's version of a command behaves differently, the page says so.

  • ls: list the files in a folderThe ls command lists files in the Linux and Mac terminal. Learn ls -l, -a, -h, -t, -R, how to read the long listing, and wildcards, with real output.
  • cd, pwd, mkdir and rmdir: move around and make foldersMove between folders with cd, see where you are with pwd, and create or remove folders with mkdir and rmdir in the Linux and Mac terminal.
  • cp and mv: copy, move and renameCopy files and folders with cp and move or rename them with mv in the Linux and Mac terminal. Options -r, -i, -n and -v, and how to avoid overwriting.
  • rm: delete files and foldersThe rm command deletes files for good in the Linux and Mac terminal. Learn rm -i, -r and -f, why rm -rf is dangerous, and a safe deleting routine.
  • cat, less, head and tail: read text filesRead text files in the Linux and Mac terminal: cat prints a file, less pages through it, head and tail show the start and end, and tail -f follows a log.
  • grep: search inside filesSearch text with grep in the Linux and Mac terminal: ignore case, line numbers, count, invert, search folders, whole words and simple patterns.
  • find: locate files by name, size and dateLocate files with the find command in Linux and Mac: by name, type, size and date, and act on the results with -exec, with safe examples.
  • chmod, chown and sudo: permissionsUnderstand Linux and Mac file permissions: read the rwx letters, change them with chmod in letters or numbers, change owner with chown, and use sudo.
  • ps, top and kill: see and stop running programsSee what is running with ps and top and stop a stuck program with kill, killall and pkill in the Linux and Mac terminal, with the signals explained.
  • df and du: disk spaceCheck free disk space with df and find what is using it with du in the Linux and Mac terminal, with -h for readable sizes and ways to find big folders.
  • tar, zip and unzip: archivesBundle and compress files with tar and zip in the Linux and Mac terminal: create, list and extract .tar.gz and .zip archives, with the options explained.
  • ping, curl and wget: network commandsTest a connection with ping, fetch pages and files with curl and wget, and look up addresses with ip, ifconfig and dig in the Linux and Mac terminal.
  • echo, variables and PATHPrint text with echo, set and export variables, and understand the PATH variable in the Linux and Mac terminal, including how to add a folder to PATH.
  • Pipes and redirection: join commands togetherJoin commands with the pipe and send output to files with > and >> in the Linux and Mac terminal: stdin, stdout, stderr and 2>&1, with real examples.
  • sort, uniq, wc and cut: work with lines and columnsSort lines, remove duplicates, count and pick columns from text files with sort, uniq, wc, cut and tr in the Linux and Mac terminal, with examples.

Where to begin

  1. ls lists a folder.
  2. cd, pwd and mkdir move you around and make folders, and explain paths.
  3. cp and mv copy, move and rename.
  4. cat, less, head and tail read text files.
  5. grep searches inside files.
  6. Pipes and redirection join commands together. This is the idea that makes the rest powerful.
  7. rm deletes, permanently. Read the whole page first.

Then, as you need them: find to locate files, sort, uniq, wc and cut for working with lines and columns, chmod, chown and sudo for permissions, ps, top and kill for running programs, df and du for disk space, tar and zip for archives, ping and curl for the network, echo, variables and PATH, and man, --help and history for getting help.

Things every command here shares

  • Options start with a dash, as in ls -l. Single letters can be joined: ls -la.
  • Capital and small letters matter: File.txt and file.txt are different on Linux.
  • Help is built in: man command, or command --help.
  • Ctrl + C stops a running command.
  • Tab completes names, and the up arrow recalls earlier commands.
  • No news is good news. A command that succeeds often prints nothing.

Linux and the Mac

Both descend from Unix, which is why the same commands work on each. The differences are small: the Mac's versions of some tools accept slightly different options, home folders are under /Users on a Mac and /home on Linux, and software is installed with different tools. The pages mention these where they matter.

The same commands also work on Windows inside the Windows Subsystem for Linux, and many of them in Git Bash.

sudo

Some instructions put sudo in front of a command. It runs that one command with the administrator's powers, after asking for your password. Nearly everything on these pages needs no sudo. Treat any command that does as one to understand fully before running. The chmod page explains more.

This is an independent learning site. It is not connected with Microsoft, Apple or any Linux distribution. Windows, macOS and other names belong to their owners. Try commands first in a practice folder, never on files you cannot afford to lose.
