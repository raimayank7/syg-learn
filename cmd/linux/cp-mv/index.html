Linux and Mac commands

cp and mv: copy, move and rename

cp copies and mv moves. mv is also how files are renamed: there is no separate rename command for a single file. Both work quietly, and both will overwrite an existing file without asking unless told otherwise.

Copying a file

Source first, destination second. If the destination is a folder, the copy goes inside it and keeps its name.

Several files can be copied into a folder at once. The last name is the destination.

Copying a folder

cp refuses to copy a folder unless you add -r, for recursive, meaning "and everything inside".

Moving

The file is gone from where it was. Moving within one disk is instant, however large the file, because only its entry is moved.

Renaming

Renaming is moving to a new name in the same place.

It works on folders too.

The danger: silent overwriting

If the destination file exists, both commands replace it. No question, no warning, no Recycle Bin.

Danger. cp new.txt report.txt destroys the old report.txt if there is one. mv does the same. The previous contents cannot be brought back.

Three options protect you.

OptionEffect
-iinteractive: ask before overwriting
-nno clobber: never overwrite, skip silently
-vverbose: say what is being done

The second command did nothing, because todo.txt exists and -n forbids replacing it.

Many people make -i the default by adding alias cp='cp -i' and alias mv='mv -i' to their shell's start-up file. Some Linux systems do this for the administrator account already.

Keeping dates and permissions

A plain copy is a new file with today's date. -p preserves the original's date, time and permissions. -a, for archive, does that and copies folders fully, and is the option to use for a faithful copy of a folder: cp -a project project-backup.

Checking a pattern first

Before a wildcard copy or move, look at what the pattern matches.

echo shows how the shell will expand it: echo mv *.txt archive/ prints the full command without running it.

Copying to another computer

cp works on disks attached to this computer. For copying over a network, the tools are scp and rsync. rsync -av source/ destination/ is also excellent for local backups, since it copies only what has changed.

Danger. rsync --delete removes from the destination anything not in the source. With the two paths the wrong way round, it empties the folder you meant to protect. Add -n for a dry run, which only reports what would happen.

Common mistakes

  • Forgetting -r for a folder.
  • A trailing word mistaken for a destination: mv a.txt b.txt c.txt fails unless c.txt is a folder.
  • Overwriting by renaming onto an existing name.
  • Unquoted names with spaces.

The Windows equivalents are copy, move and ren.
