Linux and Mac commands

ping, curl and wget: network commands

A few commands answer most questions about a network: is it reachable, what is my address, and can I fetch this file? They were not run for this page, since the results would describe a real network. Sample outputs are illustrations.

ping: is it reachable?

On Linux and the Mac, ping carries on for ever unless you give -c with a count, or press Ctrl + C. Each line is one reply, with the time taken. The summary gives the share lost.

You seeIt usually means
steady repliesthe connection is fine
"Request timeout" or no repliesthe other end is off, unreachable, or ignores pings
"cannot resolve" or "Name or service not known"the name could not be found: a DNS problem
"Network is unreachable"your own computer has no connection

Test in three steps: your router, then a public address by number, then a site by name. Where the replies stop tells you where the fault is.

What is my address?

On Linux, ip addr lists each network interface with its addresses. Look for the line beginning inet under your Wi-Fi or Ethernet interface. hostname -I prints just the addresses.

On a Mac, use ifconfig, or for one answer: ipconfig getifaddr en0.

These are the addresses on your local network. The address the internet sees is your router's.

curl: fetch from a web address

curl requests a web address and prints what comes back.

That prints the page's HTML. More useful forms:

CommandDoes
curl -I URLshow only the headers: status, type, size
curl -o file URLsave to a file with the name you give
curl -O URLsave using the name from the address
curl -L URLfollow redirects
curl -s URLsilent: no progress display
curl -C - -O URLresume an interrupted download

The first line of the headers is the status. 200 means success, 301 and 302 mean the page has moved, 404 means not found, and numbers from 500 mean the server has a problem.

wget: download files

wget is made for downloading. It saves to a file by default and retries if the connection drops.

-c continues a partial download. wget comes with most Linux systems. The Mac has curl but not wget unless you install it.

Never pipe a download into a shell without reading it

Installation instructions often look like this:

Danger. That line downloads a program from the internet and runs it at once, with your permissions, without your seeing a word of it. With sudo in it, the program has full control of the computer. Do this only for software you have decided to trust, from its official site, over https. The careful way is to download first, read, and then run: curl -o install.sh URL, then less install.sh, then sh install.sh.

DNS: names into addresses

Both ask a DNS server for the address behind a name. If these fail while pinging a numeric address works, the trouble is with name lookup, not the connection.

traceroute: the route

It lists each router on the way to the destination. Lines of stars are routers that did not answer, which is common. What matters is where replies stop for good. On Linux it may need installing. tracepath is a close relative that is usually present.

Open ports and connections

On Linux, ss -tuln lists the ports on which your computer is listening for connections. The older netstat -tuln does the same where it is installed. On a Mac, lsof -i -P | grep LISTEN.

ssh: a terminal on another computer

ssh user@host opens a command line on a remote computer that you have an account on. It asks for the password, or uses a key file. exit closes the connection. scp file user@host:folder/ copies a file to it.

Stay within your own network

Testing your own connection and your own computers is fine. Scanning or probing systems that belong to someone else, without their permission, may be against the law and against your internet provider's terms. If you are learning, practise on your own machines.

The Windows equivalents are ipconfig, ping and tracert.
