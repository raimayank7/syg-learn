Wildcards, quotation marks and spaces in file names

Two small topics cause a large share of command-line mistakes: patterns that match more or fewer files than expected, and file names with spaces in them. Both are simple once the rules are clear.

Wildcards

A wildcard is a character that stands for others in a file name. With one, a single command can act on many files.

[a-z]one character in the range (Linux, Mac)[a-m]*names starting with a to m

Look before you act

A pattern is a guess about which files exist. Before using one with a command that changes anything, test the same pattern with a listing command.

Who expands the pattern?

On Linux and the Mac, the shell replaces the pattern with the list of matching names before the command starts. The command never sees the star. Two things follow.

  • If nothing matches, the pattern is passed along unchanged, and the command complains that no such file exists.
  • A pattern meant for the command itself, as with find -name "*.txt", must be in quotation marks to stop the shell expanding it first.

On Windows, each command does its own matching, and commands differ slightly in how they treat patterns.

A stray space is a disaster

rm *.txt and rm * .txt differ by one space. The second has two arguments: *, meaning every file, and .txt. It deletes everything in the folder. The same applies to del * .txt on Windows. Read a deleting command once more before pressing Enter, and list first.

Hidden files

On Linux and the Mac, * does not match names that begin with a dot. rm * leaves hidden files behind, and cp * backup/ does not copy them. To include them, name them: .[!.]*, or copy the folder itself with cp -r.

Windows short names and .

On Windows, *.* matches every file, including those with no dot in the name. Wildcards also match against the old short form of long names, which occasionally makes a pattern match a file whose visible name does not seem to fit.

Spaces in names

The command line splits what you type at spaces. A name such as annual report.txt is read as two names, annual and report.txt.

The first attempt went wrong in an instructive way. cat looked for two files. It could not find one called annual, and it printed a different file, report.txt, which happened to exist. With a deleting command, that kind of slip removes the wrong file. Quotation marks made the name one argument.

Single and double quotation marks

On Linux and the Mac, the two kinds differ.

FormInside it
"double"spaces are kept; variables such as $HOME are replaced
'single'everything is literal; nothing is replaced

In the Windows Command Prompt, only double quotation marks group words. Single ones are ordinary characters.

Wildcards inside quotation marks do nothing

A pattern in quotation marks is not expanded.

That looks for a file literally named star-dot-txt. To use a pattern with a path that has spaces, quote the part with spaces and leave the wildcard outside: ls "my files"/*.txt.

A file called Tom & Jerry.txt typed without quotation marks is read as two commands. Put the whole name in quotation marks.

In scripts, always quote variables

A variable holding a file name should be in double quotation marks every time it is used: rm "$file", not rm $file. Without them, a name with a space becomes two arguments, and a name with a star is expanded. Unquoted variables are behind many scripts that work in testing and fail on real data.

Names that begin with a dash

On Linux, a file called -notes.txt is mistaken for an option. Put ./ in front, or -- before it: rm ./-notes.txt or rm -- -notes.txt. The double dash means "no more options follow".

Choosing names that cause no trouble

For files you will handle from the command line:

  • use small letters, digits, dashes and underscores;
  • avoid spaces, and characters such as & $ ! * ? ( ) #;
  • do not start a name with a dash or a dot unless you mean it to be hidden;
  • write dates as year-month-day, 2026-11-12, so that names sort in date order.

report-2026-11.txt needs no quotation marks anywhere. Report (final) #2.txt needs them everywhere.
